# v0.2 Plan

Date: 2026-06-02

## Product Decision

Domain Guardian should not force an agent to read every context file. The v0.2 workflow starts with
an index, selects the relevant domain area, then reads only the linked files unless the task is
ambiguous or policy-changing.

## New Capabilities

- `index.md`: maps keywords, code paths, owners, risk, and required brief topics.
- `domain_brief.py`: includes selected Index context before deeper rules and flows.
- `analyze_diff.py`: scores changed files and diff text against Index entries and reports domain risk.
- `check_brief.py`: validates that a Domain Impact Brief exists and has required sections.

## Intended Workflow

1. Read `.domain-guardian/index.md`.
2. Match the task and changed files to an Index entry.
3. Read only the linked files first.
4. Generate a Domain Impact Brief.
5. Analyze the diff and require a valid brief for medium/high-risk changes.
6. Update the Index when a new domain area or code path is discovered.

## Why This Matters

The plugin becomes more practical for larger codebases. It reduces token waste, gives agents a
clear first stop, and creates a path toward CI or pre-commit enforcement without needing a remote
service.
